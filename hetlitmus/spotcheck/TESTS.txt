# HetLitmus dev-tier spot-check subset: fewest tests, widest machinery touch.
#
# Five harnesses standing at the ends of the axes the emitted machinery is
# parameterised by -- proc count, GPU lanes, scope, which side of the cycle is
# annotated, and which kind of outcome column the target arrives on.  Nothing
# here is compared against a prediction.
#
# Format: <test> <TAB> <role> <TAB> <rationale>.  pack-bundle.sh reads field 1
# and FAILS if a name is not an emitted harness dir; it reads field 2 to find
# the `3-widest-launch' row and refuses to pack unless that row's launch is
# still the corpus maximum on both launch axes.  ladder.sh runs every field 1.

MP-cg-sys-fence-2s	1-two-sided	TWO-SIDED: both halves carry an ordering annotation (CPU DMB SY, GPU fence.sc.sys), which is the only way a het cycle is closed from both ends. Its geometry is the subset's smallest -- NPART=2, one block, one GPU lane -- so what a rung reads off it is the annotation and not the launch.
MP-cg-cta-acquire	2-one-sided	ONE-SIDED: the only annotation is on the GPU proc, and it is an acquire at cta scope -- the narrowest scope the corpus emits, so the residual weakness sits on a GPU reader whose acquire does not reach the CPU thread. Same geometry as the two-sided pick (NPART=2, one block, one GPU lane), so the pair isolates the CPU-side annotation as the only difference.
IRIW-gcgc-sys-fence	3-widest-launch	THE LARGEST LAUNCH IN THE CORPUS: NPART=4 across 2 GPU blocks -- the maximum on both axes.  NPART counts the participants of the rendezvous, and this row's four are its four procs, two of them GPU procs. It is the shape whose rendezvous and scaffolding could outgrow a cooperative launch, and the only pick here where that would show.
R-cg-sys-relaxed	4-both-column-kinds	BOTH KINDS OF OUTCOME COLUMN AT ONCE: its condition is `exists (1:r0=0 /\ [y]=2)', a register outcome AND a final-memory outcome on the same row, so the target arrives only if the read buffer and the location's own slot are both read back. Its register read is the fr-against-init one, which returns the initial value in the weak case.
2+2W-cg-sys-relaxed	5-store-only	STORE-ONLY (both procs write; no tested load), so the harness reads NO register at all: its whole outcome vector is the two locations' own slots, which is the readout path no register-bearing row exercises. The rung reads the frame this row prints, not whether a column arrived: a readout that lost the location columns prints NOT-OBSERVED here and passes.
