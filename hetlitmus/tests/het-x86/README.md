# `tests/het-x86` — the committed (x86_64, hip) pair fixture

Four het tests with an x86-64 CPU column, plus the control map the emitter
resolves beside them. It exists so that gates and cram tests which need the **(x86_64, hip)
pair** (`litmus/hetMachine.ml`) do not have to generate the whole 411-test
x86 corpus first — `tests/het/generate-x86.sh` needs `hetgen7` on `$PATH`, which a
cram sandbox does not have.

**`make hetlitmus-x86fixture` keeps it honest.** Everything here is an extract, so
it can go stale in silence while every gate that reads it keeps passing;
`hetlitmus/verify/x86fixturecheck.py` runs the generator into a temp dir and
compares the four `.litmus` files byte for byte and each map row verbatim. If it
reddens, **re-cut from a fresh run — do not edit these files to match.**

It is **not** a corpus. `corpus-gate.sh` counts `tests/het` and
`tests/gpu-only` only, and nothing here is generated by, or checked against,
`generate.sh`.

Four `.litmus` files, all copied verbatim from a `generate-x86.sh` run, so they
are the same renderings the real x86 lane emits:

* `MP-cg-sys-relaxed-x86_64.litmus` — at the lattice floor and `Canary=self`:
  this test **is** the Layer-B canary, so it co-runs nothing and is the
  single-instance case. It is also the canary the other three co-run.
* `MP-cg-sys-acqrel-2s-x86_64.litmus`, `S-cg-sys-fence-x86_64.litmus` — the
  three-instance (T + mu(T) + canary) case, so the cram tests that read a `.hip`
  render see the co-run arena and not only the single-instance path. `MP`'s
  mu(T) is the canary itself; `S`'s is `S-cg-sys-relaxed-x86_64`, which is why
  that file ships too.
* `S-cg-sys-relaxed-x86_64.litmus` — at the lattice floor, and the mu(T) the
  `S` row names. A control the emitter cannot resolve is a refusal, so a fixture
  that names one has to carry it.

and the file the emitter resolves beside them:

* `control-map-amd.csv` — their four rows, copied from the re-keyed map
  `generate-x86.sh` writes. This is the file the emitter reads for mu(T) and the
  canary. It is a four-row EXTRACT of the committed original in `tests/het`, not
  an independent judgement; regenerate it from there if a row ever moves.
